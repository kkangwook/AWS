0. 하드웨어 vs 소프트웨어
-하드웨어:  눈에 보이고 손으로 만질 수 있는 ‘딱딱한 기계 부품’
	ex)  CPU(중앙처리장치), RAM(==메모리,기억장치), GPU(그래픽처리장치), 하드디스크, 본체, 화면, 배터리
-소프트웨어:  눈에 보이지 않지만 기계를 움직이게 하는 ‘프로그램과 명령어’
	ex) 운영체제, 어플리케이션, 프로그램

1. 클라우드란?
누군가 소유하지 않은 우리 모두의 컴퓨터
예시1) 스타벅스 커피머신은 클라우드임-> 때문에 모든 스타벅스의 커피 맛(온도,산미 등)은 동일
예시2) 테슬라 자동차: 바퀴 4개 달린 클라우드
예시3) 우주선의 엄청난 데이터들이 클라우드에서 계산된다(마소의 애저-azure)
원래 옛날부터 쓰던 1.중앙서버에 접속, 2.모바일등의 것들이 클라우드 비스무리한거였는데 전송 속도 빨라지면서 클라우드라 개념 지어지고 불리게 됨
-> 과거에서 부터 쓰인 개념들이 체계화되고 서비스화 되면서 클라우드 개념 정립됨

클라우드가 좋은 서비스 인건 맞지만 적절하게 사용되어야 하고 특히 관리하는 사람의 실력이 중요. 아니면 비용폭탄!!

5년전 클라우드 사용하는 큰기업들은 30~40% ->현재 60~70퍼 ->아직까지도  무궁무진한 성장 가능성
brainless robot: 팔다리만 있음, 머리(CPU,메모리)없음 but 네트워킹을 통해서 클라우드에서 계산해서 움직임 -> 머리없기 때문에 매우 쌈!! 
	-> 모든 산업의 비용이 떨어질수있음을 의미
모든 산업, 그리고 다양한 산업에 클라우드 적용 가능

@@직접 써본 클라우드: 구글 코랩 -> 연산에 필요한 cpu, ram, GPU등의 고성능 하드웨어를 구글 클라우드 데이터센터를 통해 원격으로 제공 
	-> 유료버전으로 GPU의 A100으로 크고 복잡한 연산까지도 경험 -> transformer bert의 1억1000만개의 파라미터 개수도 연산가능
	-> PaaS(개발프로그램 + 하드웨어)와 SaaS사이(서비스를 이용한다는점)이지만 정확히 말하자면 PaaS
     추가적으로: 넷플릭스, 유튜브, 멜론, 구글드라이브, 카톡, 캔바, 이메일 <- 얘네들은 SaaS

2. SaaS(사쓰)(software as a service, 서비스형 소프트웨어): 소프트웨어 빌려줌
: 클라우드 공급자가 완성된 애플리케이션을 호스팅하고, 사용자는 인터넷 브라우저나 앱을 통해 접속해 구독료를 지불하고 사용하는 클라우드 기반 소프트웨어 모델
  ( 로컬PC에 서비스 설치할 필요없이 웹 브라우저만 있으면 어디서나 접속, 사용 가능 + 구독형임 + 서비스의 자동 업데이트, 유지 보수)
 ex) 넷플릭스(영상 다운없이 구독하고 실시간으로), 멜론(음악저장없이), 구글드라이브(내 pc대신 인터넷에 대용량 파일 저장), 카톡(카카오 서버에 대화내용 저장), 캔바(포토샵 프로그램 없이 포토샵사용)
즉 개발한 소프트웨어(프로그램,어플)를 클라우드를 통해 이용자들한테 배포하고 업데이트하고 유지 보수

요즘 대세는 SaaS이며 스타트업의 80퍼 이상이 SaaS
그리고 이런 SaaS는 대부분 구독서비스: 기업에는 안정적인 재원마련, 고객에게는 귀차니즘 해결
그리고 이런 구독서비스에서 이용자의 구독 유지를 위해서는 기업이 데이터를 통한 분석뿐만 아니라 기업의 진정성과 인간미도 같이 들어가 있어야한다


이 외에도:
-PaaS(파쓰)(platform as a service): 개발자가 원하는 앱이나 웹사이트를 직접 만들 수 있도록 **개발 환경**을 인터넷으로 빌려주는 서비스
	- 서버(전부준비된서버), 운영체제(윈도우나 리눅스), 데이터베이스(체계적인저장공간), 개발프로그램 -> **개발플랫폼**을 동시에 제공
	-ex) Firebase, Heroku, AWS Elastic Beanstalk
-IaaS(아이아스)(Infrastructure as a Service): 빈 컴퓨터를 빌려주는것==**인프라**를 제공
	- 하드웨어(CPU, 메모리,스토리지+하드디스크(저장공간)),  네트워크, 가상머신(VM)==가상서버
	-ex) AWS EC2(아마존 가상컴퓨터), Google Compute Engine

따라서 
1. IaaS: 빈 컴퓨터(서버)만 빌린다 -> 하드웨어만 빌려줌
2. PaaS: 컴퓨터 + 운영체제 + 데이터베이스 + 개발 프로그램까지 빌린다 -> 하드웨어 + 개발용 소프트웨어 빌려줌
3. SaaS: 다 완성된 프로그램 자체를 빌린다 -> 소프트웨어만 빌려줌
-> 보통 PaaS로 개발자가 서비스 만들면 이 서비스를 SaaS로 이용자들한테 서비스 제공!!!
또한 PaaS에 IaaS도 포함되는 개념이라고도 볼 수 있음

1. 거시적으로 살펴보기 @그림1,2
	-네트워크의 기본 구조: 그래프 형태(호스트 + 네트워크 장비 + 통신매체 + 메시지) 
		노드(점) + 간선(링크/선) 으로 이루어진 구존
		노드는 기기, 간선은 유선 혹은 무선의 연결매체
		그리고 이 구조로 메시지를 전달
		
		호스트(host): 우리가 쓰는 컴퓨터나 폰은 이 그래프 구조의 제일 가장자리에 있음 <- 이게 호스트(+ 서버컴퓨터, 스마트워치, ai냉장고 등)
			-> 호스트에서 정보를 최초로 받아 송신하고 또 다른 호스트가 마지막 최종으로 그 정보를 수신하는 구조
		중간 노드(라우터, 공유기, 스위치): 주로 네트워크 장비
			-> 호스들끼리 주고받는 정보가 목적지까지 안전하게 안정적으로 송수신 될 수 있도록 돕는 역할
			- 스위치:같은 네트워크 내부 연결(기기와 기기 연결) 
			- 라우터:서로 다른 네트워크 연결(by인터넷 연결) + 통신 신호의 경로를 정해줌
			- 공유기(집에서는 공유기=라우터): 여러 기기가 인터넷을 함께 사용하도록 하는 장치+ IP주소를 할당해줌
		링크(간선)==통신매체: 노드간의 연결을 지어주는 매체
			1. 유선 연결 매체: 케이블
			2. 무선 연결 매체: 와이파이
		
		=> 그리고 이들을 다 활용해서 메시지를 전달

	-네트워크의 분류 @그림 3,4,5,6,7,8
		-범위에 따른 분류
			-LAN: 가까운 지역을 연결한 근거리 통신망(가정, 사무실, 학교 등 한정된 공간)
			-WAN: 먼 거리를 연결한는 광역 통신망(하나의 LAN그룹이 WAN을 통해 다른 LAN그룹과 통신)
				-ISP: WAN을 구축하고 관리하는 특별한 업체(ex-SKT, KT, LG)

		-메시지 교환 방식에 따른 분류
			-회선교환 네트워크: 호스트 간에 메시지를 주고 받기 전 회선(메시지전송로)를 미리 예약/설정하고 그 회선을 통해서만 메시지를 주고 받는 네트워크
				-ex) 전화망(전화 전에 상대방과의 회선을 미리 예약/설정하고 그 회선만으로 메시지 주고 받음
				-하지만 회선을 예약해놓고 사용하지 않으면 이용 효율이 낮아지는 구조-> 요즘 많이 사용하지는 않음
			-패킷교환 네트워크: 메시지를 '패킷' 단위로 쪼개어 송수신하는 방식, 이후 받을때 재조립
				-회선을 예약할 필요 없이 각 호스트들이 본인들이 보내고 싶은 정보를  패킷으로 쪼개어 남들도 같이 사용하는
				회선에  겹쳐지지않게 동시에 보내는 방식으로 이용 효율이 높음
				-따라서 오늘날 인터넷 환경에서 제일 많이 사용하는 방식
				
				-패킷(택배,소포): 페이로드 + 헤더 + (트레일러)
					-페이로드: 실질적인 데이터
					-헤더: 부가정보로 이 패킷이 어디서 만들어져 어디로 보낼지 등의 정보를 포함
					-트레일러: 패킷의 끝 표시 + 오류 검출 코드(오류있는지확인)

2. 미시적으로 살펴보기(실제 정보 전송에서 어떤 일들이 벌어지는지)
	-프로토콜: 네트워크 세상의 언어(http, https, ftp, ip, TCP, UDP)이며 종류가 여러개고 각 목적과 특징이 다름
		-> 호스트가 보내는 패킷의 언어가 타 호스트 및 거치는 중간노드한테도 통해야함
		-> 즉 노드간에 정보를 올바르게 주고 받기 위해 합의된 규칙이나 방법
		-http는 http끼리, ftp는 ftp끼리 사용
		but!!!! -> 일상속 언어와 달리 통신과정에서 일반적으로는 여러 프로토콜을 함께 사용하긴 함(by 캡슐화)
		ex) https는 http에 비해 보안상 더 안전한 프로토콜이다
		ex) TCP는 UDP에 비해 일반적으로 느리지만 신뢰성이 높은 프로토콜이다
		ex) IP는 패킷을 수신지까지 전달하기 위해 사용되는 프로토콜이다(주소의 역할?)
			-> 프로토콜마다 목적과 특징이 다르다!!!!!
			-> 따라서 패킷은 프로토콜마다 목적과 특징에 맞는 정보(헤더)를 포함한다!!!
			-> 프로토콜마다 포함된 정보(헤더)는 다를수있다

	-네트워크 참조 모델: 패킷을 전송하고 수신하는 과정까지의 정형화되고 계층적인 모델
		-예시:
			보낼때: 선물할 책 준비(6계층) -> 책 포장지로 감쌈(5계층) -> 택배상자에 담음 -> 택배상자 밀봉 
			          -> 택배기사가 확인할수있게 송장(헤더)붙임 -> 택배상자를 택배기사에게 전달(1계층)
			받을때(정확히 역순): 기사로부터 택배상자 받음(1계층) -> 기사가 확인한 송장 제거(2계층) -> 상자개봉
			          -> 포장된 책 꺼냄 -> 포장용지 제거 -> 책 확인(6계층)
		-종류들:
			-OSI모델: (상위)응용계층-표현 계층-세션 계층-전송 계층-네트워크 계층-데이터 링크 계층-물리 계층(하위)
			-TCP/IP모델: (상위)응용 계층-전송 계층-인터넷 계층-네트워크 액세스 계층(하위)
		-상위계층에 있을수록 우리가 일상적으로 사용하는 응용프로그램(웹브라우저, 게임등)과 밀접하게 맞닿아있음
		-아래 계층일수록 네트워크 하드웨어와 가까워진다(물리계층)==순수 전기적인 신호
		
	-캡슐화와 역캡슐화
		-네트워크는 참조 모델이라는 여러 계층으로 이루어져 있고 각 계층마다 속해있을수있는 프로토콜도 다르다
		-캡슐화: 계층을 지날수록 페이로드에 헤더(및 트레일러<-얘는 물리계층 바로 전단계에 마지막으로 붙음)를 붙이는 과정
			(이때 페이로드+헤더는 다음층에서는 하나의 페이로드가 되고 여기에 또 헤더가 붙는 구조)
		-역캡슐화: 캡슐화되는 과정에서 덧붙은 헤더 또는 트레일러를 역순으로 제거해 나가는 과정
####################################
-트래픽: 네트워크 내의 정보량(특정 노드를 경유하는 정보량->일반적으로 트래픽은 노드에서 측정하므로)
	-이때 한 노드마다 처리할수있는 트래픽의 양은 노드마다 정해져있음
	-> 트래픽이 몰리면 과부하로 인한 성능저하가 생김
	-이때 요기서 성능을 측정하는 지표들:
		-처리율: 단위시간당 네트워크를 통해 실제로 전송되는 정보량(실시간)
			ex) bps(bits per second), Mbps(mega), Gbps(giga), pps(packets per second)
		-대역폭: 통신 매체를 통해 송수신할 수 있는 최대 정보량
			ex) bps, Mbps, Gbps, pps
		-패킷손실: 몇개의 패킷이 네트워크 이동과정에서 손실됐는지

[OSI 7계층 & TCP/IP 4계층 핵심 정리]

--------------------------------------------------
OSI 7계층
--------------------------------------------------

OSI(Open Systems Interconnection)

네트워크 통신 과정을 7단계로 나눈 모델

순서 (위 → 아래)

7. Application (응용계층)
6. Presentation (표현계층)
5. Session (세션계층)
4. Transport (전송계층)
3. Network (네트워크계층)
2. Data Link (데이터링크계층)
1. Physical (물리계층)

암기법

응 표 세 전 네 데 물

--------------------------------------------------
7계층 : Application (응용계층)
--------------------------------------------------

사용자가 직접 사용하는 계층: 웹 브라우저, 이메일 등 실제 서비스가 동작하는 계층

예시: HTTP, HTTPS, FTP, DNS, SMTP


#시험 단골

HTTP는 몇 계층인가?
정답 : 응용계층(7계층)

DNS는 몇 계층인가?
정답 : 응용계층(7계층)

--------------------------------------------------
6계층 : Presentation (표현계층)
--------------------------------------------------

데이터 형식 변환: 암호화, 복호화, 압축

예)JPEG, PNG, MP3

--------------------------------------------------
5계층 : Session (세션계층)
--------------------------------------------------

통신 연결 유지: 세션 생성, 세션 종료

예) 로그인 유지

--------------------------------------------------
4계층 : Transport (전송계층)
--------------------------------------------------

데이터 전달 담당

대표 프로토콜: TCP, UDP

TCP 특징: 신뢰성 높음, 순서 보장, 재전송 가능
사용 예: 웹사이트, 파일전송, 은행서비스

UDP 특징: 빠름, 신뢰성 낮음, 순서 보장 안함
사용 예: 게임, 영상통화, 실시간 스트리밍

#시험 단골

TCP는 몇 계층인가?
정답 : 4계층

UDP는 몇 계층인가?
정답 : 4계층

--------------------------------------------------
3계층 : Network (네트워크계층)
--------------------------------------------------

목적지 찾기: 어느 컴퓨터로 데이터를 보낼지 결정하는 계층
대표: IP, Router

정답 : 3계층

라우터는 몇 계층 장비인가?
정답 : 3계층

--------------------------------------------------
2계층 : Data Link (데이터링크계층)
--------------------------------------------------

같은 네트워크 내부 통신하는 역할(같은 LAN 안에서 장비 찾기)
대표: MAC Address, Switch, ethernet(이더넷)프로토콜
