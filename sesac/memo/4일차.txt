=================================NACL============================
NACL: Network access control list : 네트워크 접근 권한 관련 보안 -> 전사적(ex:회사 전체으로 관리)
	-> 서브넷별로 (SG는 서버별로)
	-> 이때 서브넷: 같은 바운더리에 있는 여러 EC2들     vs     서버별로=각 EC2 이느턴스별로
	-> aws들어가서 VPC들어가면 왼쪽에 네트워크ACL있음 -> 인바운드, 아웃바운드 규칙 편집
	-> 인바운드규칙추가: 101 ICMP -ipv4 모두 -> 0.0.0.0/0  거부
	-> 그리고 핑했는데 예상과 달리 그대로 ping가능
	-> 이는 SG는 우선순위가 없지만 NACL은 우선순위가 있음
	-> 이미 100번 규칙이 모두를 허용중이었음 -> 규칙번호를 99로 하면 숫자 낮은게 우선 적용
	-> ping이 안되는 것을 볼 수 있음 -> ping 8.8.8.8도 안됨(나가는것도 막아서)
=> 따라서 규칙번호를 잘 조합해 놓아야지 우선순위대로 NACL이 적절히 적용된다 !!!!! 

SG: 인바운드를 허용하면 아웃바운드도 함께 허용 (stateful)
NACL: 인바운드/아웃바운드 완전 별개 (stateless)

	=> 공인 ip(ex:8.8.8.0/24)로 생성하면 VPC는 8.8.8.x를 내부 네트워크로 판단 → 실제 인터넷의 8.8.8.8로 보내지 않고 VPC 내부에서 찾음 -> 구글 접속 불가

00001010.00000000.	00000000.00000000   #네트워크 + 호스트
11111111.11111111.	00000000.00000000   #서브넷마스크

범위: 10.0.0.0 ~ 10.0.255.255

서브넷 10.0.0.0/24 ~ 10.0.255.0/24 까지 총 256개의 네트워크(256개의 팀)을 구성할 수 있음
그리고 하나의 서브넷 당 255개의 호스트

서브넷1 10.0.0.0/24 = 10.0.0.1 ~10.0.0.254  # 이때 1.0은 네트워크 주소, 1.255는 브로드캐스트 주소  -> 이론적으로 총 254개의 서버를 들 수 있음
서브넷2 10.0.1.0/24 = 10.0.1.1 ~10.0.1.254
서브넷1 10.0.2.0/24 = 10.0.2.1 ~10.0.2.254
		......
현실적으로는 GW,등등 내부적으로 사용하는 주소들이 있어 3개정도 빠짐
-> 결론적으로 251개 사용

# ip주소 계산기도 있음

우리집: VPC
방: subnet
통신사에 연락해서 인터텟 놔주세요 -> 인터넷과 연결된 회선: internet gateway
이 인터넷을 나눠쓸 준비: router
각 방에서 노트북별로 인터넷함: EC2


1. VPC만들기 (방 만들기)
 VPC생성클릭 -> VPC만 -> 이름 -> IPv4 CIDR 수동 입력 -> 전체 vpc: 10.0.0.0/16 -> vpc생성
-> 왼쪽의 subnet클릭 -> 서브넷 생성 -> VPC ID는 방금내가 만든 VPC로 -> 서브넷 이름, 가용영역, 서브넷 CIDR블록 지정
-> 이때 subnetting할때 /n하고 좌우버튼 클릭하면 알아서 범위 지정
->새 서브넷 추가로 똑 같이 새로운 서브넷 생성 -> 서브넷 생성클릭 -> 2개의 서브넷이 생성된것을 볼 수 있음
-> 서브넷 클릭 -> 작업 -> 서브넷 설정 편집 -> 퍼블릭 IPv4 주소 자동 할당 활성화

2. EC2 생성(노트북 사오기)
EC2 생성(순서는 상관없음, 짜피 모든게 다 지어져야 그제서야 모든게 작동) -> 새로 만든 VPC보안그룹도 먼저 생성(인바운드에만 !!!!ssh적용되게) -> 적용시켜줌 -> EC2생성
-> 보면 프라이빗이 10.0.1.27 or 10.0.0.166 로 잘 나옴

3. 인터넷게이트웨이 생성(집에 인터넷 연결)
왼쪽 인터넷 게이트 웨이 클릭 -> 이름만 -> 바로 인터넷 게이트웨이 생성 -> 생성된 애 클릭 -> 작업 -> VPC에 연결 -> 만든 VPC에 연결
-> 즉 인터넷선이 연결되었다.

4. 라우팅 테이블 생성(방끼리 선 라우터로 연결시키고 라우터를 IGW에 또 연결)
라우팅 테이블 생성 -> 이름 -> 내가 만든 VPC 생성  
-> 이때 서브넷 끼리는 라우터에 의해 연결이 되어있지만 라우터와 IGW가 연결이 안되어있음!!!!
-> 라우팅 편집하기전에 리프레시해서 이름없는게 실제 우리가 만든 라우터일수도 있음 -> 라우팅편집 -> 대상을 0.0.0.0/0, 대상을 인터넷 게이트웨이로 -> 밑에 my-vpc-igw클릭


실제 만드는 순서
1. VPC 생성(큰 ip생성됨)
2. Subnet 지정(ip 논리적으로 나눔)
3. IGW 생성해 VPC에 연결
4. Router생성하고 VPC연결하면 서브넷들-라우터 끼리 연결 됨 -> 이후 라우터를 IGW에 연결하여 서브넷에도 인터넷연결되게 함 
5. SG생성하고(인바운드만 건들기) EC2를 생성하면서 만든 VPC안의 subnet안에 가상머신 생성하면 끝
