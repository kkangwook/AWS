- 웹 접속 오류 확인 순서
  1. sudo tcpdump -i enX0 -nn port 80
     → 80번 패킷이 서버까지 들어오는지 확인
     → 아무것도 안 뜸 : 서버까지 패킷이 안 옴(IP, 보안 그룹, 방화벽 확인)
     → Flags [S] : 클라이언트가 연결을 요청함
     → Flags [S.] : 서버가 연결 요청을 수락함
     → Flags [.] : 연결 확인
     → Flags [P.] : 실제 데이터를 전송함
     → Flags [F.] : 정상적으로 연결을 종료함
     → Flags [R.] : 서버가 연결을 거부함(해당 포트의 서비스가 꺼져 있을 가능성)

  2. sudo netstat -antp
     → 현재 서버의 TCP 연결 상태와 열려 있는 포트를 확인
     → Local Address : 내 서버의 IP와 포트
     → Foreign Address : 상대방의 IP와 포트
     → LISTEN : 해당 포트가 열려 있고 접속을 기다리는 상태
     → ESTABLISHED : 상대방과 연결된 상태
     → PID/Program name : 해당 포트를 사용하는 프로세스
     → 0.0.0.0:80 ... LISTEN : 모든 IP에서 들어오는 80번 요청을 받을 준비가 됨
     → 80번 포트가 없음 : 웹 서비스가 실행되지 않거나 다른 포트를 사용 중

  3. 패킷은 들어오지만 Flags [R.]이고 netstat에 80번이 없는 경우
     → sudo systemctl status nginx
     → Nginx가 꺼져 있으면 sudo systemctl start nginx
     → sudo netstat -antp에서 0.0.0.0:80 ... LISTEN이 나오면 정상

- 핵심
  → tcpdump : 패킷이 서버까지 도착하는지 확인
  → netstat -antp : 서버가 해당 포트를 열고 기다리는지 확인
  → tcpdump에 아무것도 안 뜸 : 서버 바깥쪽 문제
  → tcpdump에 [R.]이 뜨고 netstat에 포트가 없음 : 서버 서비스 문제
  → tcpdump에 [S], [S.], [.]이 뜨고 netstat에 LISTEN이 있음 : 네트워크 연결은 정상

--------------------디바이스 연결하기 실습---------------------------

dd if=/dev/zero of=file1 bs=1M count=1024   -> 내용이 전부 0인 1GB짜리 파일 file1을 만드는 명령어(dd: 데이터생성, 한번에1M씩복사를 1024번 복사)
	-> 3개 만들기 -> 용량부족해짐
	-> 해결법: 파일정리하거나 외장하드사기
1.	-> 디스크 추가하기(EBS-elastic block store) -> 왼쪽 EBS에서 볼륨클릭하면 기존 8GB짜리 나옴 -> 볼륨생성 클릭 
	-> 유형, 크기, 나머지 기본, 가용영역은 같은 위치에 있어야 속도가 당연히 빠름 -> 생성 -> 외장하드 생성 -> 이름 붙여주기(구분하기 위해)
	-> 체크하고 작업 -> 볼륨연결 -> 인스턴스 고르고 -> 디바이스이름 sdf (이와 같이 리소스를 원하는대로 만들고 제거하는게 프로비져닝임!!!)
	-> $ sudo dmesg= 리눅스 커널 메시지 -> HW의 변경사항들 탐리헤주는 로그 
	-> $ sudo dmesg -T로 시간기준 정렬하면 xvdf로 연결된게 보이고
	-> $ sudo fdisk -l 하면 맨 밑에 xvdf 10GiB짜리 연결된게 보임
	-> 나의 디스크에 데이터를 쓸 수 있는 규격으로 설정하는 포맷팅이 필요 (ext4방식으로 제일 많이 사용)
	-> $ sudo mkfs -t ext4 /dev/xvdf
	-> $ sudo mkdir /data
	-> $ sudo mount /dev/xvdf /data
	-> $ df -h로 확인
	-> $ sudo chown ubuntu:ubuntu /data  #로 내가 sudo없이 파일 맘대로 만들수있게하기위해 소유자/그룹 변경
	-> $touch hello.txt하면 만들수이ㅛ음
	-> $ dd if=/dev/zero of=file1 bs=1M count=1024 여러번 반복해서 다시 용량 채우기
	-> $ df -h하면 /dev/xvdf의 채워진 디스크 용량 볼 수 있음

2. 용량을 동적으로 늘리기
	-> 용량이 1GB밖에 안나음 -> EBS가서 기존 디스크 체크하고 -> 작업 -> 볼륨수정
	-> 15GiB로 늘리기 (이때 공간은 다시 줄일수없음!!!-저장을 fragmentation식으로 하므로)
	-> 수정
	-> $ sudo fdisk -l하면 15GB로 보이지만 $df -h하면 그대로 10GB로 보임

	-> resize 라는 방식이 있음( 남은 영역을 지금과 동일하게 맞춰 늘리기)

	-> $ df -h하면 늘어난것을 볼 수 있음
	-> 근데 reboot하고 df -h하면 사라져있음 -> 마운트한게 떨어져서
	-> sudo fdisk -l하면 보이기는하지만 다시 마운트 해줘야함
	-> sudo mount /dev/xvdf /data

##########################설명##########################
- sudo systemctl stop nginx
  → Nginx 종료 → 80번 포트를 받아줄 프로그램이 없어짐

- sudo tcpdump -i enX0 -nn port 80
  → Nginx가 꺼져 있어도 외부에서 보낸 80번 패킷은 서버까지 들어옴
  → Flags [R.] : 받아줄 프로그램이 없어 연결 거부(RST)

- netstat -antp
  → 현재 사용 중인 TCP 포트 확인
  → :22는 있는데 :80이 없음 → 80번을 사용하는 프로그램이 없음

- sudo systemctl status nginx
  → Nginx 상태 확인 → 꺼져있음

- sudo systemctl start nginx
  → Nginx 실행

- sudo systemctl status nginx
  → active(running) → 정상 실행

- netstat -antp
  → 0.0.0.0:80 LISTEN 확인
  → Nginx가 모든 IPv4 인터페이스의 80번 포트에서 접속을 기다리는 중

핵심:
tcpdump에 패킷이 보임 → 패킷이 서버까지 도착
0.0.0.0:80 LISTEN → Nginx가 80번 포트에서 실제로 요청을 받을 준비 완료

3. 서버에서 사용자를 위한 계정 만들어야함
sudo mysql
CREATE USER 'woohyun'@'%' IDENTIFIED BY '1234';      #%: 어디서든지 접속할수있다
GRANT ALL PRIVILEGES ON sesac.* TO 'woohyun'@'%';  #sesac에 대한 권한
mysql -h 172.31.6.107 -u woohyun -p


4. 서버에서 netstat -antp보니 127.0.0.1:3306  -> 나만 허용중 -> mysql 서버의 기본보안도 뚷어야함
cd /etc/mysql/mysql.conf.d 하고 ls하면 mysql.cnf  mysqld.cnf
-> 여기서 d(daemon)걸 봐야함
-> sudo vi /etc/mysql/mysql.conf.d/mysqld.cnf
-> bind address를 127.0.0.1에서 0.0.0.0으로 바꿈
sudo systemctl restart mysql
-> sudo netstat -antp -> 0.0.0.0:3306 이어서 누구나이제 접속가능
