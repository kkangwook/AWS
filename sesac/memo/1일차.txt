IAM 모범사례
1. Users – 개별사용자를통한권한관리
2. Password – 가장높은수준의암호정책부여
3. Rotate – 보안키를자주갱신
4. MFA – OTP 및 모바일앱 등 멀티펙터인증사용(루트사용자는반드시)
5. Groups – 그룹을통한권한관리
6. Permissions – 처음에는무조건최소한의권한만
7. Sharing – 권한공유는IAM 역할(Roles)을 통해
8. Roles – EC2 인스턴스에도부여(사람뿐만아니라서버에도할당)
9. Root – 접속금지(또는삭제)
10. Auditing & Monitoring – 감사및 확인

MFA(Multi-factor Authentication) : 비번 + OTP + 지문   이런식으로 여러 다른 인증요소 factor로 인증하는법

HTTP 프로토콜 정의 : 웹에서 클라이언트와 서버가 데이터를 주고받기 위한 통신 규칙

100 Informational (정보)
100 Continue              → 요청을 계속 진행해도 됨

200 Success (성공)
200 OK                    → 요청 성공
201 Created               → 요청 성공 + 새로운 리소스 생성됨
202 Accepted              → 요청은 접수됐지만 아직 처리 완료되지 않음

300 Redirection (리다이렉션)
300 Multiple Choices      → 여러 응답/선택지가 존재
301 Moved Permanently     → 영구적으로 다른 주소로 이동
302 Found                 → 임시로 다른 주소로 이동
303 See Other             → 다른 주소로 가서 결과를 확인
304 Not Modified          → 변경된 내용 없음 (캐시 사용 가능)

400 Client Error (클라이언트 오류)
400 Bad Request           → 잘못된 요청
401 Unauthorized          → 인증 필요
403 Forbidden             → 접근 권한 없음
404 Not Found             → 요청한 페이지/리소스 없음

500 Server Error (서버 오류)
500 Internal Server Error → 서버 내부 오류
501 Not Implemented       → 서버가 해당 기능을 지원하지 않음
502 Bad Gateway           → 게이트웨이/프록시가 잘못된 응답을 받음
503 Service Unavailable   → 서버가 일시적으로 요청 처리 불가능
504 Gateway Timeout       → 게이트웨이/프록시 응답 시간 초과)
