vpc -> routing table추가 -> sesac-vpc-private-router라는 새로운 라우터 VPC적용시켜서 생성 -> 두 router 같은 vpc에 연결됨
-> public router클릭 -> 작업 -> 서브넷 연결 편집-> pub서브넷에만 연결 -> private꺼는 pri subnet에만 연결
-> pri 창 이제 작동 안됨, public ip로 연결 안됨 -> 하지만 pri3은 pub1, pub2랑 연결이 되어있음
-> pub1에서 ssh ubuntu@3.39.225.36는 안됨 -> ssh ubuntu@10.0.30.18 -> 되긴하는데 키가 없어서
-> cmd로 우리 윈도우에서 pri1에 키 복사해줘야함 
-> scp -i C:\Users\SBA\Downloads\woohyun-sesac-vpc-key.pem C:\Users\SBA\Downloads\woohyun-sesac-vpc-key.pem ubuntu@3.38.151.208:~/woohyun-sesac-vpc-key.pem
-> 그리고 pri1에서 pub3접속해도 위험하다며 안됨
-> chmod 400 woohyun-sesac-vpc-key.pem   # 이거 사용자한테만 읽을수 있도록 돼있어야함
-> ssh ubuntu@10.0.30.18 -i woohyun-sesac-vpc-key.pem 으로 pub1에서 pri3에 프라이빗하게 접속함
-> 하지만 키를 내부에 복사에서 두면 안됨!!!!!
-> ssh-agent를 통해서 키를 전달해야함 !!!!!
-> powershell를 관리자로 실행 -> Get-Service ssh-agent | Set-Service -StartupType Manual  # 설정변경
-> Start-Service ssh-agent  로 실행
-> cmd에서 ssh-add C:\Users\SBA\Downloads\woohyun-sesac-vpc-key.pem 로 추가
-> ssh-add -l 하면 추가된 키 목록들 볼 수 있음
-> 삭제하고 싶으면 ssh-add -d C:\Users\SBA\Downloads\woohyun-sesac-vpc-key.pem
-> cmd에서 pub1로 agent를 통해 키 지정 없이 이제 접속가능해짐
-> ssh ubuntu@3.38.151.208 -A 하면 agent없이 접속가능해짐 (or ssh -A ubuntu@3.38.151.208)
-> ssh ubuntu@10.0.30.18 로 키 없이 바로 private접속 가능 (Agent가 반드시 붙어있어야함!!!!!!)

즉 public: 내가 나가고 남이 들어올수있음   vs    private: 내가 나갈수있지만(by NAT gateway) 남(외부망)이 들어올수는 없다 (내부망 제외)

-> 이때 NAT을 pri3이 있는 서브넷에 넣으면 안됌!!!!!!!!!!!!!!!!!!! -> 짜피 연결 안돼있어서
@-> NAT은 pub1이나 pub2가 속한 서브넷에 넣는다!!!!!!!!!!!!!!!!!!!!!!!
-> 그래야 pri3이 pub1 ec2에 연결되고 여기서 NAT타고 밖으로 나간다!!!
-> 퍼블릭 -> 탄력적ip할당 (나갈때 공인ip받기 위해) -> 생성
-> 프라이빗 라우팅 테이블 -> 라우팅 편집 -> 라우팅 추가 -> 0.0.0.0/0(모르는 ip가 왔을때 전부)를 NAT 게이트웨이로 보내라+ natgw -> 변경사항저장
-> 즉 pri3이 이동할때 경로몰라서 private router로 이동 -> 그러면public router로 이동 -> 그래도 몰라서 NAT gateway가 받음 -> 얘가 밖으로 내보냄
-> nginx다운 -> 하지만 ip로 접속해도 아무것도 안뜸
-> 왜냐!!! : 외부로 나가 다운받아올 수 있지만 외부에서 내부로 들어오는거는 당연하므로!!!!!
