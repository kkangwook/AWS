############################# 개념 #############################
- SG는 인스턴스 수준에서 적용/ NACL은 서브넷 기준에서 적용
	SG는 인바운드만 건든다(아웃바운드 냅둠) 
- MFA(Multi-factor Authentication) : 비번 + OTP + 지문   이런식으로 여러 다른 인증요소 factor로 인증하는법
- LAN(2계층)은 MAC주소(기기들고유번호)를 참고해서 스위치가 연결 (이더넷 프로토콜 사용)
- WAN(3계층)은 라우팅테이블+라우터로 LAN에 ip부여해 전송되게(이때 한 라우터는 펼쳐나갈 수 있는 방향이 2~3개 존재)
- DHCP가 네트워크 장치(기기)에 IP 주소와 설정 정보를 자동으로 할당
- NAT가 사설ip나갈떄 공인ip로 바꿔줌+해당기기의 포트설정 -> 다시 들어올때 인지해서 받아들이고 포트번호로 해당 고유 기기로 돌아오게함
	외부에서 내부는 안됨 
- VM의 네트워크 종류
	NAT: 서로 같은 사설 ip가져도 괜찮으며 사설ip를 공인으로 전환해 인터넷으로 나가게해줌
	Bridged Adapter: VM을 직접 LAN에 연결
	Host-only: windows Host와 VM끼리의 통신을 위한 LAN
	Internal Network(Intnet): VM끼리만 통신
	NAT Network: VM끼리 통신 + 인터넷 통신 가능
- IP Forwarding: 한 네트워크 인터페이스에서 받은 IP 패킷을 다른 네트워크 인터페이스로 전달하는 라우터의 핵심기능
- sudo tcpdump -i 랜카드 -nn port n 하면 출발지 IP -> 목적지 IP나오고
	- 패킷자체가 안보임: 서버까지 요청이 못 옴(IP문제/SG/라우팅/NACL 등 확인)
	- 패킷은 보이는데 응답이 없음: 서버의 서비스상태/netstat으로 포트확인 /ufw방화벽 등을 확인
- route -n 에서 0.0.0.0은 테이블에 길 없으면 디폴트로 보낼곳을 의미
- 같은 VPC에 있으면 사설ip로 서로 접속 가능
- netstat -antp 해서 ip범위와 : 포트  부분이 listen 되어있어야 해당 서비스 접속 가능

--------------------------------2. 2일차: 네트워크 다른 VM 연결하기

VM1 어댑터들 : NAT, Host-Only(192.168.~), Intnet1(10.10.10.1/24)
VM2 어댑터들 : NAT, Host-Only(192.168.~), Intnet1(10.10.10.2/24), Intnet2(10.20.20.2/24)
VM3 어댑터들 : NAT, Host-Only(192.168.~), 		           Intnet2(10.20.20.3/24)

NAT은 필수로 있어야하고 각 cmd에서 Host-Only로 ssh연결, 각 VM들은 Intnet으로 통신
-> 이때 VM1, VM3끼리는 네트워크 달라서 서로 ping 안됨(라우터 필요)
-> VM1 터미널에서 sudo route add -net 10.20.20.0/24 gw 10.10.10.2
	: 10.20.20.0/24 범위로 가고싶으면 일단 10.10.10.2로 가라고 라우트테이블 설정
-> VM2에서는 sudo sysctl -w net.ipv4.ip_forward=1
	: ip forward기능 활성화해서 자기 목적지가 아닌 IP 패킷을 다른 인터페이스로 전달해서 라우터처럼 동작하게 함
-> VM3 터미널에서는 sudo route add -net 10.10.10.0/24 gw 10.20.20.2
	: 받은 신호 다시 돌려보내야 하므로 반환 경로 설정
=> 최종적으로 VM1, VM3 ping 가능해짐

-------------------------------10. 3-tier VPC 구축
조건: 
VPC: 10.0.0.0/16
	az-1			az-3
pub-sub1(10.0.10.0/24)	pub-sub2(10.0.20.0/24)
 	web1(nginx)

pri-sub3(10.0.30.0/24)	pri-sub4(10.0.40.0/24)
	was3(flask)		was4

			pri-sub5(10.0.50.0/24)
				DB5(mysql)

@목표: was3과 db5는 private이며 web1에서 was3 접속하게하고, was3에서 DB5에 접속하게 하기

1. VPC생성(10.0.0.0/16) 
2. 서브넷 생성: 서브넷 위처럼 5개 생성 -> 서브넷1과2만 자동 공인ip할당
3. 라우터 생성 및 연결: 라우팅 테이블 하나는 이미 자동 생성(router1) + 추가로 pri용 라우터생성(router2) -> 서브넷연결편집으로 router1에 pub만, router2에 pri만
4. IGW생성 및 라우터1에 연결: igw생성-> vpc에 연결 
	-> 라우터1로 가서 라우팅 편집 -> 라우팅추가: 0.0.0.0/0 + 인터넷게이트웨이(igw)
5. NAT 게이트웨이 생성 및 라우터2로 연결: natgw생성-리전별(신규)로 편리하게(원래는 pub-sub1 or 2에) + vpc지정 + 자동 탄력적 ip
	-> 라우터2로가서 라우팅편집 -> 라우팅 추가 0.0.0.0/0 + NAT게이트웨이(natgw)에 연결 
6. 미리 security group생성:
	web-sg: ssh + http (전부 0.0.0.0/0)
	was-sg: ssh + flask(5000) (전부 0.0.0.0/0)
	db-sg: ssh + mysql(3306) (전부 0.0.0.0/0)
7. EC2생성(web1,was3,db5):
	web1: t3.micro + pub-sub1 + web-sg
	was3: t3.medium + pri-sub3 + was-sg
	db5: t3.large + pri-sub5 + db-sg
8. ssh-agent: powershell를 관리자로 실행 -> Get-Service ssh-agent | Set-Service -StartupType Manual  # 설정변경 -> Start-Service ssh-agent  로 실행
	-> cmd에서 ssh-add [key] 로 추가 -> ssh-add -l 로 추가된 키목록 확인
