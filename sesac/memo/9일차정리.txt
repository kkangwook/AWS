sg로 소스집어넣으면 ip바껴도 사용가능하다는 장점
scale up(성능향상)은 별로
sacle out(EC2 인스턴스 수 늘리기)이 좋음

필요한 개념:
	1. auto scale group만들기 필요: EC2 인스턴스 자동 그룹 관리
	2. Launch Configuration / Launch Template :  ASG에서EC2 인스턴스를시작할때 사용하는설정
	3. Scaling Policies : 어떤 조건으로 scaling할건지
	4. CloudWatch Alarms : 특정 조건이 되면 경보를 생성 -> 트리거 생성
	5. Health Checks : 인스턴스의상태를모니터링하여비정상적인인스턴스를감지하고교체

ASG가 꺼질때 랜덤으로 꺼지므로 생성될때도 순서상관X, 무작위로 down돼도 상관없는 서버만 AS쓰도록 한다!!!!!!
∎ 로드밸런서: 로드밸런서가 기존 ASG 인스턴스에 대해 트래픽 분산하다고 클라우드워치가 모니터링하면서 부하가 있다고 판단하면
	오토스케일링하면서 인스턴스 늘어나고 로드밸런서는 추가로 확장된 인스턴스에 까지도 트래픽 분산!!
∎ 로드밸런서: 여러 EC2를 하나의 그룹으로 묶어 하나의 엔드포인트화 한거임. 
	      그래서 저 하나의 엔드포인트에 접속해도 두 군데에 분산처리되어 들어가는거

로드밸런서 종류
	L4: 4계층(전송계층) 부하를 줄이는 방법으로 포트번호 기준으로 트래픽 분산 
	L7: 7계층에 부하를 줄이는 방법(HTTP, HTTPS)

로드밸런싱 알고리즘:
	1. 라운드로빈: 순서대로 각 서버에
	2. 가중라운드로빈(각 서버마다 스펙이 다르므로 가중치를 줌)
	3. 최소연결: 현재 가장 적은 연결을 가진 서버로
	4. IP해싱:  IP주소 특징마다 분류해서 각각 다른 서버로

ELB(Elastic Load Balancer):  AWS에서제공하는로드밸런싱서비스
	1. Application Load Balancer (ALB) : HTTP/HTTPS 트래픽에최적화된L7 로드밸런서
	2. Network Load Balancer (NLB) : TCP/UDP 트래픽에최적화된L4 로드밸런서
	3. Gateway Load Balancer (GLB) : 가상어플라이언스를통합하기위해사용되며, 네트워크트래픽을처리함

----------------------------auto scaling 실습------------------------
AMI나 쉘스크립트로 데이터가 포함된 시작 템플릿 생성
→ 시작 템플릿으로 Auto Scaling Group 생성
→ 대상 추적 정책(cpu50%)을 설정하고 부하를 주어 EC2 자동 증가/감소 확인
→ SNS를 연결하여 ASG의 인스턴스 개수 변화 이메일로 확인
→ 로드밸런서와 대상 그룹 생성
→ 대상 그룹에 만든 ASG 연결
→ 로드밸런서의 DNS에 부하를 주어 EC2가 증설되고 대상 그룹에 자동 등록되는지 확인

1. AMI만들기: 기존 EC2에 적용된 코드들 복사(∎인스턴스유형, VPC,서브넷,sg등 다 안정해짐!!!!)
	기존 EC2클릭 -> 이미지 및 템플릿 -> 이미지 생성 -> 이름만 다르게 해서 이미지 찍어냄
	-> AMI로 -> AMI클릭하고 AMI로 인스턴스 시작 -> 새로운 인스턴스 생성

2. 시작 템플릿 제작: 자동으로 만들때 어케 만들지 구성
	시작 템플릿 생성 -> ∎AMI or 제일 밑 사용자데이터에 쉘스크립트(sudo는 빼기)
	 -> ∎인스턴스, VPC등 고르거나 나중에 고르기 -> 리소스 태그로 키에 name해서 이름지정 
	-> 고급세부정보 세부 CloudWatch 모니터링 활성화 해서 1분마다 모니터링하게
	-> 생성 -> (수정하면 수정하고 기본버전 설정으로 바꿔줘야함)
	-> 생성된 템플릿으로 인스턴스 시작 -> EC2 생성됨

3. 시작 템플릿으로 Auto Scaling Group 생성: 생성하면 EC2가 원하는 용량만큼 생성돼있음
	auto-scaling그룹 생성 -> ∎시작 템플릿 넣어줌 -> ∎수동으로 인스턴스 유형 추가+가중치지정
	-> VPC + 서브넷 -> (기존 로드밸런서에 연결가능)
	-> ∎원하는/최소/최대 용량 결정 -> ∎대상 추적 크기 조정 정책 선택(ex:CPU)
	-> (SNS연결 가능) -> 마지막페이지 그룹생성!!

4. 필요시 추가 설정
	4-1. ASG로 생성된 EC2에 가서 작업 -> 모니터링 및 문제해결 -> 세부 모니터링 활성화: 1분주기로 모니터링됨
	4-2. SNS: 주제생성 -> 다음단계 -> 표준 -> 생성
		-> ASG로가서 -> 활동 -> 알림생성 -> SNS주제로 방금만든 SNS 선택 -> 생성  #∎SNS에 ASG알림 추가
		-> SNS로 다시가서 구독생성 -> 프로토콜에 이메일(문자도가능) -> 내 이메일 -> 구독 생성  #∎이 SNS를 구독하겠다
		-> 스팸함에 가있어서 스팸해제 + confirm subscription클릭

5. 다른 EC2에서 ASG 인스턴스에 과부하보내기 실습
	다른 EC2들 에서 sudo apt install apache2-utils -y
	-> ab -n 10000000 -c 200 http://ASG-ip/     # 얼만큼 보낼지, 한번에 얼마보낼지, 어디로 보낼지
	=> ASG그룹 들어가서 -> 모니터링 -> Auto Scaling 그룹 지표 수집활성화 -> 옆에 EC2클릭 -> 50%이상되면 auto scaling발생!!!!! 
	-> 2개였던게 4개가 됨 -> 이후 트래픽 줄으면선 시간지나면(느리게) 2개->1개까지로 줄어듬

6-1. 로드밸런서: ASG의 EC2들을 하나의 엔드포인트로 설정해 사용자들을 각 EC2에 고르게 분배도록
	EC2 왼쪽 로드밸런서 생성 -> ALB or NLB -> 인터넷 경계
	-> VPC 선택-> ∎가용역역 a,c둘다 선택 + 각각의 web-subnet선택 AWS에서 주소 할당
	-> sg로 web-sg -> HTTP 80 
6-2. 대상그룹생성(인스턴스로 묶겠다) -> ∎대상그룹 선택 or 생성(클릭가능) -> 다음창으로
	-> 인스턴스들을 하나로 묶을수도 있지만(+보류중으로포함) 우리는 ∎비어있게
	-> 대상그룹생성 -> 각 EC2들 전부 정상떠야함 (헬스체크로 200떠야함)
6-1. 로드밸런서로 다시 돌아와 ∎대상그룹 선택 -> 생성 
6-3. ASG로 가서 통합 -> 로드밸런싱 편집 
	∎애플리케이션, 네트워크 또는 게이트웨이 로드 밸런서에서 방금 만든 대상 그룹 클릭 -> 업데이트
	-> 해당 대상그룹 들어가면 대상합계1 돼있음 
	-> 로드밸런서의 DNS이름으로 http://DNS이름 형식으로 접속 가능
		(여러 EC2라도 하나의 엔드포인트로 분산처리되어 접속!)
	-> 똑같이 부하주면 EC2 scale out
	-> -> 대상그룹도 2개로 늘어나며 초반에 정상1, 비정상1이다가 정상2로 바뀜
