VirtualBox 네트워크 실습 최종 정리
-------------------------------------------------------
[오늘 실습의 전체 흐름]
1. VM도 실제 PC처럼 네트워크 인터페이스(랜카드)를 가질 수 있음
2. NAT를 이용해 VM에서 인터넷 사용
3. Host-Only로 Windows ↔ VM 통신
4. Internal Network로 VM ↔ VM 전용 네트워크 구성
5. VM 3대를 서로 다른 내부 네트워크로 구성
6. 서로 다른 네트워크끼리는 바로 통신할 수 없다는 것을 확인
7. 가운데 VM2를 Router처럼 만들어 VM1 ↔ VM3 통신
8. 이를 위해 Routing Table + IP Forwarding 설정

=======================================================
@1. VirtualBox 네트워크 종류
=======================================================
NAT
→ VM이 인터넷에 나가기 위한 네트워크
→ VirtualBox가 NAT 역할을 함
→ 기본 NAT에서는 VM마다 독립된 NAT 환경을 가질 수 있음
→ 그래서 여러 VM이 10.0.2.15를 가져도 충돌하지 않을 수 있음

Bridged Adapter
→ VM을 실제 LAN에 직접 연결
→ 실제 공유기의 DHCP 서버로부터 IP를 받을 수 있음

Host-Only
→ Windows Host ↔ VM 통신을 위한 가상 LAN
→ 같은 Host-Only 네트워크의 VM끼리도 통신 가능
→ 인터넷 통신용은 아님

Internal Network
→ VM ↔ VM끼리만 통신하는 가상 LAN
→ Host/인터넷과 기본적으로 연결되지 않음
→ DHCP가 없다면 IP를 직접 설정

NAT Network
→ 여러 VM이 같은 NAT 네트워크에 참여
→ VM끼리 통신 + 인터넷 통신 가능

=======================================================
@2. DHCP: VM에게 IP 주소 같은 네트워크 설정을 자동으로 나눠주는 역할을 함
=======================================================
DHCP Server
→ IP 주소, Subnet Mask, Gateway 등의 네트워크 설정을 자동으로 할당

Host-Only 예시)
Windows Host → 192.168.56.1
DHCP Server → 192.168.56.100
VM 할당 범위 → 192.168.56.101~199

주의)
enp0s8 = DHCP 서버 X
enp0s8 = VM에 붙어 있는 네트워크 인터페이스(랜카드)
DHCP 서버가 enp0s8에 IP를 할당해주는 것

→ Router가 없으므로 직접 통신 X

VM1 → 10.1.1.1/24

→ 둘 다 10.1.1.0/24
→ 같은 네트워크이므로 직접 통신 O

→ 네트워크 인터페이스를 실제로 지나가는 패킷 관찰

→ Host-Only 인터페이스의 패킷 관찰

sudo tcpdump -i enp0s3 -nn
→ NAT 인터페이스를 지나가는 패킷 관찰

-i → 관찰할 인터페이스 지정
-n → IP를 이름으로 변환하지 않음
-nn → IP와 Port 번호를 이름으로 변환하지 않고 숫자 그대로 표시

=======================================================
10. intnet 이름이 중요한가?
=======================================================
O 중요함.

VirtualBox에서 같은 Internal Network 이름을 가진 랜카드끼리 같은 가상 LAN에 연결됨.

VM1 enp0s9 → intnet
VM2 enp0s9 → intnet
→ 서로 연결 O

VM2 enp0s10 → intnet2
VM3 enp0s9 → intnet2
→ 서로 연결 O

VM1 → intnet
VM3 → intnet2
→ 서로 다른 가상 LAN이므로 직접 연결 X

즉 Internal Network의 이름은
"어느 가상 스위치/LAN에 꽂을 것인가"를 정한다고 생각하면 쉬움

@11. 처음 ping 테스트 결과
=======================================================
[VM1]
ping 10.10.10.1 → 성공 (자기 자신)
ping 10.10.10.2 → 성공 (같은 intnet의 VM2)
ping 10.20.20.3 → 실패 (다른 네트워크의 VM3)

[VM2]
ping 10.10.10.2 → 성공 (자기 자신의 intnet IP)
ping 10.10.10.1 → 성공 (VM1)
ping 10.20.20.2 → 성공 (자기 자신의 intnet2 IP)
ping 10.20.20.3 → 성공 (VM3)

[VM3]
ping 10.20.20.3 → 성공 (자기 자신)
ping 10.20.20.2 → 성공 (같은 intnet2의 VM2)
ping 10.10.10.1 → 실패 (다른 네트워크의 VM1)

※ 자기 자신의 IP로 ping하면 정상적으로 성공하는 것이 맞음

=======================================================
@12. 그런데 VM1 ↔ VM3도 통신하게 만들고 싶음
=======================================================
현재:

VM1 ───── VM2 ───── VM3
10.10.10   ↑        10.20.20
            │
       양쪽을 모두 앎

→ VM2를 Router로 만들면 됨

하지만 2가지 설정이 필요함.

① VM1/VM3에게 반대편 네트워크로 가는 길(Route)을 알려줌
② VM2가 받은 패킷을 반대편으로 전달(IP Forwarding)하게 함

=======================================================
@13. Routing Table이란?
=======================================================
Routing Table
→ "어떤 목적지로 갈 때 어디로 보내야 하는지" 저장한 길찾기 표

확인:
route -n

또는:
ip route

예)
10.10.10.0/24 → enp0s9
10.20.20.0/24 → ???

VM1은 처음에는 10.20.20.0/24로 가는 길을 모름.

그래서 VM1이 VM3(10.20.20.3)로 보내려고 해도:
"10.20.20.x로 가는 길이 없네?"
→ 기본 경로(Default Route) 등을 확인
→ 원하는 VM3 내부망으로 가지 못함

=======================================================
@14. VM1에 Route 추가
=======================================================
VM1에서 실행:

sudo route add -net 10.20.20.0/24 gw 10.10.10.2

뜻:
"10.20.20.0/24 네트워크로 가고 싶으면
VM2의 10.10.10.2에게 보내!"

구조:

VM1
10.10.10.1
   │
   │ 목적지 10.20.20.x
   ↓
Gateway
10.10.10.2
   ↓
 VM2
   ↓
10.20.20.x
   ↓
 VM3

즉 VM1에게
"VM3 마을에 가려면 VM2에게 물어봐"
라고 길을 알려준 것

=======================================================
@15. 그런데 이것만 하면 완전한 통신이 안 됨
=======================================================
VM1이 VM2까지 패킷을 보냈다고 해도
VM2가 그냥 자기에게 온 패킷이라고 생각하고 끝내면 안 됨.

VM2가:
"이건 내 것이 아니라 VM3에게 전달해야겠네"
하고 반대쪽 랜카드로 전달해야 함.

이 기능이 IP Forwarding.

=======================================================
@16. IP Forwarding ⭐
=======================================================
IP Forwarding
→ 한 네트워크 인터페이스에서 받은 IP 패킷을
   다른 네트워크 인터페이스로 전달하는 기능
→ Router의 핵심 기능

VM2에서 확인:

sudo sysctl -a | grep ip_forward

또는 더 간단히:
sysctl net.ipv4.ip_forward

0 → Forwarding 꺼짐
1 → Forwarding 켜짐

VM2에서 활성화:

sudo sysctl -w net.ipv4.ip_forward=1

→ VM2가 Router처럼 패킷을 전달할 수 있게 됨

구조:

VM1
10.10.10.1
   ↓
VM2의 10.10.10.2
   ↓
[IP Forwarding]
   ↓
VM2의 10.20.20.2
   ↓
VM3
10.20.20.3

즉 네가 적은
"뭔가 라우터로 만들어서 연결 안 된 걸 연결한다"
→ 맞음 O

=======================================================
@17. 그런데 돌아오는 길도 필요함 ⭐
=======================================================
VM1 → VM3만 길을 알려주면 끝이 아님.

VM3가 VM1에게 응답을 돌려줘야 함.

그래서 VM3에도 Route 추가:

sudo route add -net 10.10.10.0/24 gw 10.20.20.2

뜻:
"10.10.10.0/24로 가려면 VM2의 10.20.20.2에게 보내"

최종적으로:

VM1
10.10.10.1
   │
   │ ① VM1 → VM3
   ↓
10.10.10.2
[   VM2   ]
[ Router  ]
10.20.20.2
   ↓
   │
VM3
10.20.20.3

그리고 응답:

VM3
10.20.20.3
   │
   │ ② VM3 → VM1
   ↓
10.20.20.2
[   VM2   ]
[ Router  ]
10.10.10.2
   ↓
VM1
10.10.10.1

18. 그래서 정확히 어느 VM에서 무슨 명령?
=======================================================
[VM1에서 실행]
sudo route add -net 10.20.20.0/24 gw 10.10.10.2

뜻:
→ VM3쪽 10.20.20.0/24 네트워크는 VM2에게 보내


[VM2에서 실행]
sudo sysctl -w net.ipv4.ip_forward=1

뜻:
→ VM2를 Router처럼 동작시켜 양쪽 네트워크의 패킷 전달


[VM3에서 실행]
sudo route add -net 10.10.10.0/24 gw 10.20.20.2

뜻:
→ VM1쪽 10.10.10.0/24 네트워크는 VM2에게 보내


정리:

VM1
sudo route add -net 10.20.20.0/24 gw 10.10.10.2

VM2
sudo sysctl -w net.ipv4.ip_forward=1

VM3
sudo route add -net 10.10.10.0/24 gw 10.20.20.2

@20. tcpdump는 여기서 왜 사용?
=======================================================
tcpdump
→ 실제 패킷이 어느 랜카드를 지나가는지 확인

예를 들어 VM1 → VM3 ping을 할 때 VM2에서:

sudo tcpdump -i enp0s9 -nn
→ VM1쪽(10.10.10.x)에서 들어오는 패킷 확인

sudo tcpdump -i enp0s10 -nn
→ VM3쪽(10.20.20.x)으로 나가는 패킷 확인

즉:

VM1
 ↓
VM2 enp0s9
 ↓
[Forwarding]
 ↓
VM2 enp0s10
 ↓
VM3

를 눈으로 확인하는 것


enp0s3를 tcpdump하면:
sudo tcpdump -i enp0s3 -nn

→ NAT/인터넷용 랜카드의 패킷을 보는 것

따라서 VM1↔VM3 내부 라우팅을 관찰하려면
VM2의 enp0s9 / enp0s10을 보는 것이 더 직접적임

=======================================================
@21. route -n에서 0.0.0.0은?
=======================================================
0.0.0.0
→ 보통 Default Route를 의미

쉽게:
"라우팅 테이블에 더 정확한 길이 없으면 이쪽으로 보내"

VM1이 처음에 10.20.20.3으로 가는 전용 Route가 없으면
10.20.20.0/24 길을 모르기 때문에 Default Route 등을 확인하게 됨.

그래서 우리가 직접:

10.20.20.0/24 → 10.10.10.2

라는 길을 Routing Table에 추가한 것.

-------------------------------------------------------
VirtualBox VM 3대 라우팅 실습 핵심
-------------------------------------------------------

[가장 중요한 핵심]

VM끼리 직접 통신하려면 단순히 intnet 이름만 같으면 되는 것이 아님.

직접 통신 조건은 2가지:

1. 같은 L2 네트워크에 연결되어 있어야 함
   → VirtualBox에서는 같은 Internal Network 이름에 연결

2. 같은 IP 네트워크 주소(같은 Subnet)를 사용해야 함
   → ex) 10.10.10.1/24와 10.10.10.2/24
   → 둘 다 네트워크 주소가 10.10.10.0/24

즉,
같은 intnet + 같은 Subnet → 직접 통신 가능
같은 intnet + 다른 Subnet → Router 없이는 직접 통신 불가
다른 intnet + 같은 IP대역 → 서로 다른 가상 LAN이므로 직접 통신 불가

=======================================================
5. VM1에서 해야 할 명령
=======================================================

VM1 터미널에서: route -n으로 확인
	sudo route add -net 10.20.20.0/24 gw 10.10.10.2

뜻: → "10.20.20.0/24 네트워크로 가려면 VM2의 10.10.10.2로 보내"

확인: route -n
=> destination(최종목표)에 10.20.20.0, gateway(중간경로)에 10.10.10.2

확인 후 테스트: ping 10.20.20.3
=> 아직 VM2 Forwarding / VM3 돌아오는 길이 없어 실패

=======================================================
6. VM2에서 해야 할 명령
=======================================================

VM2는 가운데 Router 역할을 할거임 by ip forward
	ip_forward: Linux가 자신에게 온 패킷을 다른 네트워크로 넘겨줄 수 있게 하는 기능

현재 Forwarding 확인: sudo sysctl -a | grep ip_forward (sysctl→ Linux 커널의 설정값을 확인하거나 변경 -> 모두보기 -> 이중 ip_forward들어간 행 보기)

결과가: net.ipv4.ip_forward = 0  => 이러면 Router처럼 전달하지 않는 상태

ip forward기능 활성화: sudo sysctl -w net.ipv4.ip_forward=1   # 값을 1로 바꿔줌

확인: sysctl net.ipv4.ip_forward

결과: net.ipv4.ip_forward = 1

→ VM2가 한 인터페이스로 들어온 패킷을 다른 인터페이스로 전달할 수 있음

=======================================================
7. VM3에서 해야 할 명령: 돌아오는 길도 중요함
=======================================================
일단 route -n으로 라우팅 테이블 확인 -> 경로 없음

VM3 터미널에서: sudo route add -net 10.10.10.0/24 gw 10.20.20.2
	뜻: → "10.10.10.0/24 네트워크로 돌아가려면 VM2의 10.20.20.2로 보내"

확인: route -n
=> destination(최종목표)에 10.10.10.0, gateway(중간경로)에 10.20.20.2

=======================================================
8. 최종적으로 어디서 어떤 코드?
=======================================================

[VM1]
sudo route add -net 10.20.20.0/24 gw 10.10.10.2

[VM2]
sudo sysctl -w net.ipv4.ip_forward=1

[VM3]
sudo route add -net 10.10.10.0/24 gw 10.20.20.2

10. tcpdump로 확인: 네트워크 인터페이스(랜카드)를 실제로 지나가는 패킷을 실시간으로 잡아서 보여주는 명령어
	-> 컴퓨터 랜선앞에 설치하는 CCTV
	-> ICMP패킷이 만들어짐
=======================================================

VM1                    VM2                         VM3
10.10.10.1 ─────→ 10.10.10.2 | 10.20.20.2 ─────→ 10.20.20.3
                		  enp0s9       enp0s10

VM2에서: sudo tcpdump -i enp0s9 -nn → VM1쪽 네트워크를 감시
	VM1에서 ping하면 뜸: VM1에서 VM2로 들어오는 패킷이 보임

VM2에서 sudo tcpdump -i enp0s10 -nn → VM3쪽 네트워크를 감시
	VM2가 VM3로 전달하는 패킷이 보임

VM1
10.10.10.1
   ↓
[VM2 enp0s9]
   ↓ tcpdump로 확인
[IP Forwarding]
   ↓
[VM2 enp0s10]
   ↓ tcpdump로 확인
VM3
10.20.20.3

즉 tcpdump를 통해
VM1 → VM2 → VM3
VM3 → VM2 → VM1

# 구조
1. VM1이 10.20.20.3으로 ping 보냄
2. VM1 라우팅 테이블 확인
   → 10.20.20.0/24는 10.10.10.2(VM2)로 보내라고 되어 있음
3. 패킷이 VM2의 enp0s9로 들어옴
4. VM2는 ip_forward=1이므로 패킷을 버리지 않고 전달
5. VM2 라우팅 테이블 확인
   → 10.20.20.0/24는 enp0s10 쪽에 직접 연결되어 있음
6. enp0s10으로 패킷을 내보냄
7. VM3(10.20.20.3)가 받음
8. VM3가 reply를 다시 VM2를 통해 VM1로 돌려보냄

=======================================================
11. 오늘 실습 핵심 한 줄
=======================================================

VM1과 VM3는 서로 다른 Subnet이므로 직접 통신 불가
→ VM2가 두 Subnet에 동시에 연결되어 있으므로
→ VM1/VM3에 Route 추가
→ VM2에 IP Forwarding 활성화
→ VM2를 Router처럼 사용
→ VM1 ↔ VM3 ping 성공
