----------------이론----------------
sg로 소스집어넣으면 ip바껴도 사용가능하다는 장점
rds-sg에는 ssh필요없음 -> 짜피 접속못해서 -> only 3306에 was-sg소스로
VPC끼리는 IPv4 CIDR같아도 괜찮
실제 회사는 bastion안쓰고 따로 사설망 구축하고 거기의 VPN 게이트웨이로 AWS접속
RDS는 proxy_jump가 불가: 따로 was ec2접속-> RDS로 접속가능(was ec2연결 + sg로 3306에 was허용하므로) 
RDS는 무조건 multi-az로 생성됨 -> db1장애나면 db2에서 대신
RDS는 proxy_jump가 불가

sg로 소스집어넣으면 ip바껴도 사용가능하다는 장점
scale up(성능향상)은 별로
sacle out(EC2 인스턴스 수 늘리기)이 좋음

필요한 개념:
	1. auto scale group만들기 필요: EC2 인스턴스 자동 그룹 관리
	2. Launch Configuration / Launch Template :  ASG에서EC2 인스턴스를시작할때 사용하는설정
	3. Scaling Policies : 어떤 조건으로 scaling할건지
	4. CloudWatch Alarms : 특정 조건이 되면 경보를 생성 -> 트리거 생성
	5. Health Checks : 인스턴스의상태를모니터링하여비정상적인인스턴스를감지하고교체

ASG가 꺼질때 랜덤으로 꺼지므로 생성될때도 순서상관X, 무작위로 down돼도 상관없는 서버만 AS쓰도록 한다!!!!!!
∎ 로드밸런서: 로드밸런서가 기존 ASG 인스턴스에 대해 트래픽 분산하다고 클라우드워치가 모니터링하면서 부하가 있다고 판단하면
	오토스케일링하면서 인스턴스 늘어나고 로드밸런서는 추가로 확장된 인스턴스에 까지도 트래픽 분산!!
∎ 로드밸런서: 여러 EC2를 하나의 그룹으로 묶어 하나의 엔드포인트화 한거임. 
	      그래서 저 하나의 엔드포인트에 접속해도 두 군데에 분산처리되어 들어가는거

로드밸런서 종류
	L4: 4계층(전송계층) 부하를 줄이는 방법으로 포트번호 기준으로 트래픽 분산 
		-서비스를 다른 서버의 서비스로 보내기
	L7: 7계층에 부하를 줄이는 방법(HTTP, HTTPS)

로드밸런싱 알고리즘:
	1. 라운드로빈: 순서대로 각 서버에
	2. 가중라운드로빈(각 서버마다 스펙이 다르므로 가중치를 줌)
	3. 최소연결: 현재 가장 적은 연결을 가진 서버로
	4. IP해싱:  IP주소 특징마다 분류해서 각각 다른 서버로

ELB(Elastic Load Balancer):  AWS에서제공하는로드밸런싱서비스
	1. Application Load Balancer (ALB) : HTTP/HTTPS 트래픽에최적화된L7 로드밸런서
	2. Network Load Balancer (NLB) : TCP/UDP 트래픽에최적화된L4 로드밸런서
	3. Gateway Load Balancer (GLB) : 가상어플라이언스를통합하기위해사용되며, 네트워크트래픽을처리함

ASG -> automatic scaling -> 예약된 작업 생성으로 예약도 가능

2. VM1의 Nginx를 Reverse Proxy로 만들어, 다른 VM의 웹페이지를 대신 받아오게 하는 실습(VM1 ip에 접속하면 VM2,3의 flask가 뜨게하기)

	(reverse-proxy: 클라이언트와 서버 사이의 중개자로 서버대신에 사람들의 요청을 받아서 분산처리)
	<구조>
	VM1-----------------*----------------VM2(이건 어댑터4끔)
	192.168.56.101        |			192.168.56.102
	nginx		  |			10.10.10.2 			3가지 intnet의 네트워크 같고 이름도 같아야함!!!!!!!!!
	10.10.10.1	  |			flask1
			  |
			  *----------------VM3
							10.10.10.3으로 바꿔줌, 이름도 intnet으로
							flask2


	VM2에서 flask설치하고 app.py파일 생성하고 app.run(host="0.0.0.0", port=5000)으로  #5000번으로열기
	-> sudo "$(which python)" app.py 로 계속 실행시켜놓음

	VM1의 nginx는 sites-enabled에 있는 심볼릭링크를 참조해서 설정 활성화하지만 실제 수정할때는 sites-available을 수정해야함
	->  sudo vi /etc/nginx/sites-available/default : location에 try_files주석처리하고 그 밑에 proxy_pass http://10.10.10.2:5000; 
	-> sudo nginx -t로 문제없는지 확인 -> sudo systemctl restart nginx -> 혹시몰라 sudo ufw disable
	-> 크롬으로 VM1의 ip접속하면 VM2의 flask가 잘 뜸

	VM3에서도 똑같이 flask만들고 내용만 다르게 -> sudo "$(which python)" app.py로 계속 실행시켜놓음
	-> VM1에서  proxy_pass http://10.10.10.3:5000;   으로 바꿔주고 restart만 해주면 VM3가 나옴





3. 로드 밸런싱: VM1에 접속하면 번갈아서 VM2,VM3 접속하게 하기

	VM1에서 sudo cp /etc/nginx/sites-available/default /etc/nginx/sites-available/sesac #기존 default파일을 sesac으로 복사해서 새로만듬
	-> sudo vi /etc/nginx/sites-available/sesac 해서 아래처럼 바꿈(upstream 맨 위에 추가, server안에도 추가)
	###############################################################
	upstream flask {
    		server 10.10.10.2:5000 weight=3;		# 3대1의 비중으로 요청 받겠다
     		server 10.10.10.3:5000 weight=1;		#둘다 weight지우고 두번째꺼에 대신 backup 하면 서버1 죽으면 서버2가 작동;
	}

	server {
    		listen 80 default_server;
        	root /var/www/html;
        	index index.html index.htm index.nginx-debian.html;

        	location / {
                	# proxy_pass http://10.10.10.2:5000;
                	# proxy_pass http://10.10.10.3:5000;
                	proxy_pass http://flask;             # 위의 새로 추가한 upstream flask내용을 가져오겠다
        	}

	}
	#############################################################

	-> 새로 만든 설정파일 심볼릭 링크로 활성화: sudo ln -s /etc/nginx/sites-available/sesac /etc/nginx/sites-enabled/sesac
	-> sudo nginx -t로 확인하니 중복된다고 나옴(설정파일이 default, sesac두개라)		
	-> 기존의 default설정파일비활성화 해주기: sudo unlink /etc/nginx/sites-enabled/default		
	-> sudo nginx -t로 다시 확인하니 ok사인 -> sudo systemctl restart nginx
	-> VM2, VM3둘다 켜진 상태에서 크롬으로 VM1 공인ip로 접속해서 새로고침 계속=> 이제 2번,3번 가중치에따라접속하게됨!!!!
	-> weight지우고 하나에만 backup작성하면

		(로드밸런서 ->ALB -> URL경로기반이라는 규칙)
	로드밸런서 -> 리스너 및 규칙추가 -> HTTP80 클릭(여기에 규칙추가하겠다) -> 규칙관리 -> 규칙추가
	-> 조건 경로: /shop/* -> shop대상그룹(빈 EC2) 생성 -> 선택 -> 규칙2개됨
	-> 조건 경로: /api/* -> api대상그룹(빈 EC2) 생성 -> 선택 -> 규칙3개됨

	api대상그룹 클릭 -> 대상 -> 대상등록 2개 선택(10.0.10.0/24) -> 보류중인거으로 포함 -> 등록
	shop대상그룹 클릭 -> 대상 -> 대상등록 2개 다른거로 선택 (10.0.100.0/24)-> 보류중인거으로 포함 -> 등록

	curl MywebNLB-f6c194161f5a303a.elb.ap-northeast-2.amazonaws.com/api/   -> 하면 10.0.10.0/24인것만 뜸
	curl MywebNLB-f6c194161f5a303a.elb.ap-northeast-2.amazonaws.com/shop/ -> 하면 10.0.100.0/24인것만 뜸
